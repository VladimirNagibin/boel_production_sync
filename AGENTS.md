# Инструкции для разработчиков и ИИ-помощника

## Проект и домен
- **Название**: `boel_production_sync` (пакет `bp_sync`)
- **Описание**: Асинхронный сервис для синхронизации данных между Битрикс24 и 1С: загрузка и обработка сделок, счетов, платежей, накладных, формирование отчётов, а также интеграция с маркетплейсами (Ozon) для создания и обновления сделок по заказам маркетплейса.
- **Основные сущности**: Deal (сделка), Invoice (счёт), Billing (платёжка), DeliveryNote (накладная), Company, Contact, Lead, User, Product, TimelineComment, NumberingRule, MarketplaceAccount, MarketplaceOrder, MarketplaceOrderItem, MarketplaceSyncRun.
- **Ограничения домена**:
  - Все операции синхронизации и обновления данных должны быть **идемпотентными**.
  - Строгая асинхронность: никаких блокирующих вызовов (sync I/O) в асинхронном контексте.
  - Обработка ошибок должна учитывать лимиты (rate limiting) и использовать ретраи с экспоненциальной задержкой (exponential backoff).

## Архитектура
- **Слоистая архитектура** (Clean Architecture / Hexagonal), код находится в `bp_sync/src/`:
  - `api/` — роутеры FastAPI (v1, b24, marketplaces), зависимости, валидация входящих запросов.
  - `services/` — бизнес-логика и оркестрация. Для каждой сущности принят шаблон:
    - `<entity>_services.py` — сервис/оркестрация;
    - `<entity>_repository.py` — доступ к данным;
    - `<entity>_bitrix_services.py` — клиент API Битрикс24 для сущности.
  - `services/base_services/` и `services/base_repositories/` — базовые классы.
  - `services/bitrix_services/` — общий клиент Bitrix24 API, OAuth и webhook.
  - `services/marketplaces/` — интеграция с маркетплейсами (провайдеры, маппинг в сделки).
  - `models/` — SQLAlchemy ORM-модели.
  - `schemas/` — Pydantic-схемы (запросы/ответы, внутренние DTO).
  - `db/` — подключения к PostgreSQL и Redis.
  - `migration/` — Alembic-миграции.
  - `admin/` — SQLAdmin-админка.
- **Зависимости**: допустимы только сверху вниз: API → Services → Repositories/Bitrix-клиенты → Models. Репозитории и интеграции не должны импортировать сервисы.
- **Внедрение зависимостей (DI)**: `services/dependencies.py` с ServiceLocator и contextvars; фабрики `create_<name>`, зависимости `get_<name>_dep`.
- **Работа с данными**: `SQLAlchemy 2.0` (async) + `redis.asyncio` (блокировки, хранение токенов).
- **Транзакционность**: сессии БД управляются через dependency `get_session` и контекст запроса `request_context`.
- **Кэширование**: Redis для блокировок и токенов; в рамках запроса — кэши через contextvars (`_exists_cache_ctx`, `_creation_cache_ctx` и др.).

## Стандарты кодирования
- **Форматирование и линтинг**: `black` (line-length = 79), `flake8`, `isort`, `mypy` (настройки в `bp_sync/pyproject.toml`), `pre-commit`.
- **Типизация**: использование современных конструкций Python (PEP 604 `X | Y`, PEP 585 `list[X]`). Избегать `typing.Optional`, `typing.List` в пользу встроенных типов (все функции и методы аннотированы).
- **Нейминг**: осмысленные имена, отражающие бизнес-логику. Избегать аббревиатур, кроме устоявшихся (API, DTO, ID).
  - Переменные, функции, методы: `snake_case`
  - Классы: `PascalCase`
  - Константы: `UPPER_SNAKE_CASE`
  - Приватные методы/атрибуты: с префиксом `_` (один подчёркивание)














- **Логирование**: через стандартный `logging` (конфигурация в `core/logger.py`). Используется логгер `logger = logging.getLogger("sync")` с форматом:
  `"%(asctime)s - %(name)s - %(levelname)s - %(message)s"`.
  Логи пишутся в консоль и в файл `logs/log.log` (ротация через `RotatingFileHandler`, размер задаётся настройкой `LOGGING_FILE_MAX_BYTES`).
  Дополнительный контекст можно передавать через параметр `extra` в вызове логгера.

## Документация и комментарии
- **Докстринги** (тройные двойные кавычки) — **на русском**, содержат краткое описание, аргументы, возвращаемое значение, исключения.
- **Комментарии внутри кода** — **на русском**, поясняют сложную логику.

- **Сообщения исключений и текст API-ответов** — **на английском** (для совместимости с внешними системами); логи — на русском или английском, единообразно в рамках модуля.

## Обработка ошибок

- Кастомные исключения определены в `services/exceptions.py`:
  - `BitrixAuthError` — ошибка аутентификации OAuth Bitrix24.
  - `BitrixApiError(HTTPException)` — ошибка API Bitrix24; содержит `status_code`, `error`, `error_description`; методы `is_bitrix_error()` и `is_not_found_error()`.
  - `ConflictException(HTTPException)` — конфликт при создании дубликата сущности.
  - `DealProcessingError` — ошибка обработки сделки.
  - `WebhookValidationError`, `WebhookSecurityError` — ошибки валидации и безопасности вебхуков.
  - `LockAcquisitionError`, `MaxRetriesExceededError` — ошибки получения блокировки сделки.
  - `MarketplaceApiError`, `MarketplaceSyncError` — ошибки интеграции с маркетплейсами.
- API-роутеры и обработчики вебхуков возвращают `JSONResponse` с телом вида `{"status": "success" | "error", "message": "..."}` (см. `BaseEntityClient._error_response()` и роутеры в `api/v1/`).
- Ошибки API Bitrix24 пробрасываются как `BitrixApiError`; при отсутствии сущности в Б24 (404) она помечается удалённой через `set_deleted_in_bitrix()`.
- Не подавлять исключения без необходимости: логировать с уровнем ERROR и явно обрабатывать/пробрасывать.

## Типовые задачи для ИИ

1. **Ревью предложений изменений в коде**
   - Проверять соответствие архитектуре, кодстайлу, типизации.
   - Указывать на потенциальные проблемы производительности или безопасности.
   - Ревью кода на предмет соответствия стандартам, поиска узких мест и нарушений асинхронности.

2. **Генерация unit-тестов**
   - Использовать `pytest` и `pytest-asyncio`.
   - Тесты должны покрывать бизнес-логику сервисов, репозитории тестировать с in-memory БД или моками.
   - Стремиться к покрытию ≥80%.

3. **Генерация кода**
   - Соблюдать все перечисленные стандарты.
   - Для новых эндпоинтов создавать Pydantic-схемы в `src/schemas/`.
   - Для новых таблиц — модель SQLAlchemy, alembic-миграцию и репозиторий.
   - Всегда добавлять тесты на новый функционал.

4. **Написание миграций (Alembic)**
   - Генерировать миграции через `alembic revision --autogenerate`.
   - Проверять, чтобы миграции были идемпотентными (обратимыми).

5. **Оптимизация SQL-запросов**
   - Устранение проблемы N+1, предложение индексов.

## Чего делать не нужно (Антипаттерны)
- **Не использовать синхронные библиотеки** (например, `requests`, `psycopg2`, `time.sleep`) внутри `async def` функций. Блокирующий код запрещён (используйте `asyncio.to_thread` при необходимости).
- **Не менять сигнатуры публичных API** (роутеров, интерфейсов сервисов) без явного запроса. Такие изменения требуют обновления документации и согласования.
- **Не переписывать работающий код «ради красоты»**, если это не несет практической пользы (производительность, читаемость, исправление багов).
- **Не использовать "голые" исключения** (`except Exception:` или `except:`) без логирования и проброса.
- **Не хардкодить конфигурации**, секреты и URL — использовать `pydantic-settings` и переменные окружения.
- **Не создавать циклические импорты** между слоями (например, репозиторий не должен импортировать сервисы).
- **Не игнорировать типизацию** — `# type: ignore` только в крайнем случае с комментарием причины.


## Структура проекта

```
bp_sync/src/
├── api/           # роутеры FastAPI (v1, b24, marketplaces), зависимости
├── admin/         # SQLAdmin-админка
├── core/          # настройки и логирование (settings, logger)
├── db/            # подключения к PostgreSQL и Redis
├── migration/     # Alembic-миграции
├── models/        # SQLAlchemy ORM-модели
├── schemas/       # Pydantic-схемы (запросы/ответы, внутренние DTO)
├── services/      # бизнес-логика, репозитории, Bitrix-клиенты, marketplaces
├── templates/     # шаблоны (админка, экспорт сделок)
└── main.py        # точка входа FastAPI
```

Репозитории находятся внутри `services/<entity>/`; фоновые задачи обрабатываются через очереди RabbitMQ (отдельной папки `workers/` нет).

## Дополнительные рекомендации

- **Миграции** применять через `alembic upgrade head` при деплое.
- **Коммиты**: атомарные, с осмысленными сообщениями на русском или английском (единообразие).
